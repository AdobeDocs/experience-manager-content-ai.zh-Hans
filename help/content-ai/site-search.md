# AEM内容AI 搜索入门

传统网站搜索会将访客键入的单词与内容中的单词进行匹配。 当访客使用与您的内容相同的术语时，此功能非常有效 — 但当访客提问、表示意图或只是以不同的方式表述内容时，此功能就会崩溃。 搜索是网站上访客意图的最明确信号之一，因此失败的匹配通常意味着历程失败：内容被发现、参与度下降和转化丢失。 访客越来越希望搜索能够理解他们的意思，而不仅仅是键入的内容，而且同样的意图感知基础也是创造性答案得以实现的首要原因。

AEM内容AI 搜索不会取代您网站的搜索体验，而是根据您的需求不断发展变化，从匹配关键词到理解含义和意图，再到直接回答问题。 语义搜索可在现有搜索体验的基础上添加意图感知检索，即使查询不共享内容的确切措辞，也会呈现相关内容。 创成式搜索以同样的检索基础为基础，根据您网站的内容生成符合上下文的创成答案 — 这是一个独特的步骤，与语义检索不同。

对于访客而言，这意味着更好的相关性、自然语言支持、更少的零结果搜索和更快的答案。 对于您的企业而言，这意味着更好的意图匹配、更强大的内容发现以及支持AI的搜索基础，而无需从头开始重建您的搜索体验。 对于您的团队来说，这是一个渐进式升级：您现有的搜索组件可以逐步从词典、语义移至创成功能，而无需全新的实施。

实现目标有两个决定：内容如何进入内容人工智能，以及哪个组件将内容引入访客。 连接内容，然后将搜索组件添加到页面 — 您的网站已准备好为访客提供最相关的结果和基于意图的答案。

## 先决条件 {#prerequisites}

开始之前，请确保满足以下条件：

* 您拥有一个处于活动状态的 Cloud Manager 程序，并且其中至少包含一个 AEM as a Cloud Service 环境。
* 您的用户已分配给&#x200B;**[!UICONTROL AEM用户]**&#x200B;产品配置文件（用于查看内容源）和/或&#x200B;**[!UICONTROL AEM管理员]**（用于创建和编辑它们），分配在&#x200B;**发布**&#x200B;层 — Content AI对发布的内容编制索引，而不是对创作的内容编制索引。 有关完整过程，请参阅[将用户分配给AEM产品配置文件](contentsources.md#assign-product-profile)。
* 已在&#x200B;**Adobe Admin Console**&#x200B;中配置环境的产品配置文件。

>[!NOTE]
>
>仅拥有 Cloud Manager 访问权限并不足够。 用户还需要在发布层分配AEM产品配置文件，才能查看或管理内容源。

## 步骤1a — 连接现有索引 {#option-a}

现有存储库索引会在“内容源”列表中自动显示为Source类型AEM — 按其索引内容显示，如页面、Assets或内容片段。 它们从&#x200B;**Restricted**&#x200B;开始并锁定，尚无法通过内容人工智能进行搜索。

1. 登录到[Cloud Manager](https://my.cloudmanager.adobe.com/)，选择您的项目，然后为要配置的环境打开&#x200B;**[!UICONTROL Content AI配置]**&#x200B;选项卡。
1. 查找要搜索的源（例如，**页面**）并选择其锁定图标。 只有具有&#x200B;**[!UICONTROL AEM管理员]**&#x200B;产品配置文件的用户可以执行此操作 — **[!UICONTROL AEM用户]**&#x200B;可以查看内容源，但不能更改其可搜索性。
1. 阅读&#x200B;**使源可搜索？** 仔细对话。 它警告，一旦可搜索，将不会对此索引实施Apache Oak访问控制列表(ACL) — 任何经过身份验证的用户将能够检索其所有内容。 检查&#x200B;**我了解没有强制执行访问控制(ACL)，并且此源中的所有内容都将可搜索**，然后选择&#x200B;**使可搜索**。
1. 确认状态更改为&#x200B;**可用**。 警告图标将保留在源旁边，作为绕过ACL的永久提醒。
1. 运行测试搜索以验证结果是否正确返回。

>[!WARNING]
>
>使现有索引可按这种方式搜索将完全绕过该源的Apache Oak ACL — 任何经过身份验证的用户都可以通过搜索检索其所有内容，而不管其正常存储库权限如何。 仅对您愿意完整展示的源执行这项操作。

>[!NOTE]
>
>如果您已经有一个包含网站内容（例如，页面内容）的索引，则此路径非常适合。 使用该索引，而不是设置单独的抓取机制。

## 步骤1b -抓取网站 {#option-b}

如果您还没有网站的搜索索引，请使用此路径。 Content AI自己的爬虫可为您构建和刷新库。 在整个Cloud Manager和本指南中，此抓取过程也称为&#x200B;**客户获取**。

1. 打开&#x200B;**[!UICONTROL 内容人工智能配置]**&#x200B;选项卡，与步骤1a中的操作相同。
1. 选择&#x200B;**[!UICONTROL 创建Source]**&#x200B;并填写相应的字段。 只有具有&#x200B;**[!UICONTROL AEM管理员]**&#x200B;产品配置文件的用户才能添加新内容源。

   | 字段 | 描述 |
   | --- | --- |
   | **[!UICONTROL 内容人工智能配置名称]** | 此源的唯一标识符。 创建后无法修改。 |
   | **[!UICONTROL 网站地址]** | 要抓取的根URL，例如`https://www.example.com/`。 |
   | **[!UICONTROL 排除 URL]** | *（可选）*&#x200B;抓取过程中需要跳过的 URL 模式。 |
   | **[!UICONTROL 刷新频率]** | 每周、每天、每天4×、60分钟或15分钟。 |

1. 选择&#x200B;**[!UICONTROL 创建源]**。 获取会自动开始，源将进入&#x200B;**正在索引**&#x200B;状态。
1. 监视状态，直到达到&#x200B;**可用**：

   | 状态 | 含义 |
   | --- | --- |
   | **新建** | Source刚刚创建；自动客户获取尚未开始。 |
   | **正在索引** | 正在抓取和编制索引。 |
   | **可用** | 索引完成 — 准备好提供搜索查询。 |

1. 选择源旁边的&#x200B;**搜索**&#x200B;图标并运行测试查询以确认您的内容已正确编入索引。

>[!CAUTION]
>
>**[!UICONTROL 索引编制]**&#x200B;中的源卡住？ 首先从(...)菜单重试客户获取。 如果仍然没有前进，请确认该网址可公开访问，并且您的&#x200B;**[!UICONTROL 排除URL]**&#x200B;模式没有过滤掉每个页面。

## 第2步 — 选择搜索组件 {#choose-component}

有两个组件可以在不同的基础上将搜索放置到页面上：

| | 带语义搜索的快速搜索(v3) | AEM内容AI 搜索 |
| --- | --- | --- |
| 基础 | 现有的快速搜索核心组件，已升级到v3 | 新的独立组件 — 直接调用内容人工智能API |
| 内容来源 | 您的现有网站内容已位于索引中，已扩充为语义匹配 | A Content AI Source（步骤1a或1b） |
| 创造性答案 | 否 — 仅提高现有结果列表的匹配质量 | 是 — 可选AI生成的摘要（包含源和免责声明） |
| 最佳拟合 | 已在使用快速搜索的站点，这些站点希望进行更轻的增量升级 | 建议全面提供内容人工智能功能的组件 — 语义搜索、创成搜索和自然语言搜索(NLS) |

## 带语义搜索的快速搜索(v3) {#quicksearch}

如果您的网站已使用经典[!DNL AEM]快速搜索组件，v3将添加一个选择加入&#x200B;**AI 搜索**&#x200B;切换功能，访客可以切换 — 无需使用新组件、代理或内容Source。

* 搜索仍通过与今天相同的JCR/QueryBuilder路径运行 — 结果servlet或结果的呈现方式没有任何变化。
* 当访客启用切换时，组件会在查询前面添加一个特殊标记，以便将其路由到语义匹配，而不是纯关键词全文。
* 此路径中没有生成答案摘要。 它提高了现有结果列表的匹配质量；它不会添加创新型人工智能答案。
* **第1步（内容人工智能载入）不适用于此路径。** 没有可创建或连接的内容Source — 此组件直接查询您现有的页面索引。

>[!NOTE]
>
>如果启用切换后，语义搜索无法按预期工作，请提交支持工单。

如果您希望在不采用新组件或内容源的情况下进行增量语义搜索升级，则此路径非常适合。 如果您希望获得创成式答案体验，这不是正确的路径；请使用AEM ContentAI 搜索来实现这一点。

## AEM内容AI 搜索 {#gensearch}

AEM内容AI 搜索是一个[!DNL AEM]核心组件，它允许访客直接从页面搜索Content Source，并具有语义搜索和生成性搜索功能。

>[!VIDEO](https://video.tv.adobe.com/v/3497308)

>[!NOTE]
>
>创新型搜索功能通过AI SKU单独购买。 请联系您的Adobe销售代表，为您的帐户启用该功能。

### 先决条件 {#gensearch-prerequisites}

* 已在您的项目上安装[!DNL AEM]个核心组件。
* 至少已创建一个Source内容，且处于&#x200B;**可用**&#x200B;状态。
* **AEM Content AI客户端** OSGi配置(`ContentAIClientImpl`)在创作和发布时设置，具有有效的API凭据和默认的内容Source。

有关完整的安装指南 — 使作者可以使用组件、连接其客户端库以及配置对话框 — 请参阅[核心组件文档](https://www.adobe.com/go/aem_cmp_library_cn)。
